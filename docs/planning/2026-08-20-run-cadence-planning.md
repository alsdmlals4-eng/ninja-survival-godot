## DEC-2026-08-20-013 · 5분의 의미와 4세그먼트 전투 시계

상태: `APPROVED_BY_USER_2026-08-20`

### 확정안 · 5분 세그먼트 안에 보스전을 포함하는 소프트 타임박스

`약 5분`은 일반전이 끝나는 시점이 아니라 **해당 공세의 보스와 싸우고 결산하는 목표 시간대**로 정의한다.

권장 초기 튜닝 리듬:

```text
0:00~0:30   기본 Swarm · 유파 시그니처 첫 증명
0:30~2:45   Priority / Anchor 순차 혼합
2:45        Elite 경고
약 3:00     공세 선봉대장 Elite 등장
3:00~3:30   Elite 결산 목표
3:30~4:20   공세 상승 / 오의 준비
4:20        Boss 경고
약 4:30     Boss 등장
5:00~5:30대 Boss 처치 목표
Boss 사망   RESULT → 보상 → Workbench → Fate
```

핵심:

- `5:00`은 하드 실패 타이머가 아니다.
- 보스가 살아 있으면 전투는 `overtime`으로 계속된다. 빌드가 약하다는 이유만으로 5:00에 즉사/강제 실패시키지 않는다.
- overtime 동안 보스의 `잠식 고조`로 자연스럽게 압박을 높일 수 있으나 회피 가능성을 제거하는 강제 사망 패턴은 금지한다.
- 플레이테스트에서 보스 TTK 중앙값이 계속 60~90초를 넘으면 보스 등장 시점 또는 체력/위험 예산을 조정한다.
- `약 20분`은 **4개 세그먼트의 active combat target**을 뜻한다.
- RESULT / Workbench / Fate의 플레이어 판단 시간은 active combat clock에서 제외한다.
- 따라서 실제 벽시계 플레이 시간은 Workbench 고민 시간과 boss overtime에 따라 20분보다 길 수 있다.
- 외부 마케팅에서 `정확히 20분 Run`이라고 약속할지는 Vertical Slice의 wall-clock P50/P90 측정 후 결정한다.

### 4세그먼트 의미

1. **제1 공세 · 지부 즉각 생존 / 선택 유파 잔흔 첫 조우**
2. **제2 공세 · 주변 전선 유지**
3. **제3 공세 · 반격 / 공세 근원 접근**
4. **제4 공세 · 최종 공세 / Run 최종 보스**

첫 3세그먼트는 5분 전후의 비슷한 active-combat 예산으로 맞춘다. 제4 최종 보스는 기억성을 위해 조금 긴 overtime을 허용할 수 있으나, 최종전만 3~5분 추가되어 전체 템포를 무너뜨리지 않게 한다.

### DEC-012 유파 잔흔 보스와의 연결

- 제1 공세의 5분대 보스는 `공통 보스 골격 + 선택 유파의 잠식 잔흔 키트` 구조를 사용한다.
- 봉마: 잠식 식신/봉인진.
- 천술: 원소 상태/반응 영역.
- 귀인: 근접 지속/귀혈 잔흔.
- 흑영: 표식 누적/예고 처형.
- 이 보스는 같은 유파를 봉쇄하는 하드카운터가 아니라 플레이어가 배운 유파 철학을 적의 편에서 읽게 하는 거울상이다.

## 비교에서 비채택한 안

### B · 현행 runtime처럼 5:00 일반전 종료 후 보스 등장

```text
0:00~5:00 일반전
5:00 Boss 등장
Boss 처치 후 RESULT
```

비채택 이유:
- 보스 TTK가 각 세그먼트에 추가되어 4세그먼트 active combat이 24~28분 이상으로 늘어나기 쉽다.
- Workbench까지 포함하면 실제 Run은 더 길어진다.
- 기존 `약 20분 / 4×5분` 목표와 가장 크게 충돌한다.

### C · 4분대 보스 등장 후 정확히 5:00까지 미처치 시 실패

비채택 이유:
- 사실상 DPS 체크가 되어 봉마의 준비형, 천술의 반응 누적형 같은 스타일에 불공정할 수 있다.
- 보스 패턴을 읽는 재미보다 시간 압박이 우선된다.
- 공간/빌드 판단보다 수치 최적화가 강제될 위험이 있다.

## 벤치마크 적용 원리

- 제한된 생존 시간이 명확한 전투 목표가 되는 장점은 참고한다.
- 전투 구간과 전투 사이 상점/판단 시간을 분리하는 원리를 참고한다.
- 닌자의 신에서는 이를 `active combat clock 약 20분 + Workbench/Fate 판단 시간 별도`로 변형한다.

## 5회 적대적 검토 결과

### Loop 1 · 20분 약속 왜곡

문제: Workbench 시간을 제외하면 사용자 체감 Run은 20분보다 길다.

결론: 내부 명칭을 `약 20분 전투 시계`로 사용하고, 실제 제품 카피는 Vertical Slice의 wall-clock P50/P90 측정 후 확정한다.

### Loop 2 · Boss overtime 악용/지연

문제: 무제한 overtime이면 매우 방어적인 빌드가 지나치게 오래 버틸 수 있다.

결론: 하드 즉사 타이머 대신 보스의 자연스러운 잠식 고조가 시간이 갈수록 압박을 올리게 한다. 그래도 회피 가능성은 유지한다.

### Loop 3 · 보스가 너무 일찍 느껴질 위험

문제: 4:30 등장하면 플레이어가 `5분 보스`라고 인지하지 않을 수 있다.

결론: UI/기획 문구는 `5분대 보스 결산`으로 표현한다. 4:30은 초기 튜닝 시작값이지 영구 고정 수치가 아니다.

### Loop 4 · Elite와 Boss 간격 부족

문제: 3분 엘리트가 오래 살아남으면 보스 준비 시간이 사라진다.

결론: Elite는 20~35초 안팎의 중간 시험을 목표로 하고, 45초 이상 자주 걸리면 HP/증원 예산을 낮춘다. Elite가 살아 있는 상태에서 Boss를 강제 중첩시키지 않는 것을 기본으로 한다.

### Loop 5 · 현행 코드 충돌

현재 `StageFlowController`는 `segment_duration_seconds = 300`, 시간 0에서 BOSS 요청, `segment_index >= 3`에서 COMPLETE다. 구현 계획에서 반드시 다음을 별도 migration으로 다룬다.

- 3 → 4세그먼트.
- 일반 COMBAT와 Elite/Boss 이벤트의 세그먼트 내부 시점화.
- 300초 종료 후 Boss spawn 구조를 `4분대 Boss entry + soft overtime` 구조로 변경.
- RESULT/SHOP(Workbench)/FATE 동안 active combat clock 정지.
- 기존 MVP-0~3 테스트는 새 cadence 계약에 맞춰 의도적으로 갱신한다.
- 사용자가 `기획 완료`를 선언하기 전에는 runtime을 수정하지 않는다.

## DEC-013 최종 한 줄

**`4×5분은 active combat 목표치이며, 각 세그먼트 보스는 5분대에 결산하고 초과 시 hard fail 대신 soft overtime을 사용한다. RESULT·Workbench·Fate 시간은 전투 시계에서 제외한다.`**
