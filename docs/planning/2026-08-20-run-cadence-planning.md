제품 코드·Scene·Resource·runtime은 현재 범위가 아니다. 현재 runtime은 `300초 COMBAT → BOSS` + 3세그먼트이지만 최신 승인 제품 기획은 `약 20분 / 4×5분`이므로 구현 전 reconciliation이 필요하다.

## DEC-PENDING-WORLD-013 · 5분의 의미와 4세그먼트 전투 시계

### A · 5분 세그먼트 안에 보스전을 포함하는 소프트 타임박스 · **권장**

`약 5분`은 일반전이 끝나는 시점이 아니라 **해당 공세의 유파 잔흔 보스와 싸우고 결산하는 목표 시간대**로 정의한다.

권장 리듬:

```text
0:00~0:30   기본 Swarm · 유파 시그니처 첫 증명
0:30~2:45   Priority / Anchor 순차 혼합
2:45        Elite 경고
약 3:00     공세 선봉대장 Elite 등장
3:00~3:30   Elite 결산 목표
3:30~4:20   공세 상승 / 오의 준비
4:20        유파 잔흔 Boss 경고
약 4:30     유파 잔흔 Boss 등장
5:00~5:30대 Boss 처치 목표
Boss 사망   RESULT → 보상 → Workbench → Fate
```

핵심:

- 5:00은 하드 실패 타이머가 아니다.
- 보스가 살아 있으면 전투는 `overtime`으로 계속된다. 빌드가 약하다는 이유만으로 5:00에 즉사/강제 실패시키지 않는다.
- 플레이테스트에서 보스 TTK 중앙값이 계속 60~90초를 넘으면 보스 등장 시점 또는 체력 예산을 조정한다.
- `약 20분`은 **4개 세그먼트의 active combat target**을 뜻한다.
- RESULT / Workbench / Fate의 플레이어 판단 시간은 active combat clock에서 제외한다. 따라서 실제 벽시계 플레이 시간은 플레이어의 Workbench 고민과 boss overtime에 따라 더 길 수 있다.
- 외부 마케팅에서 `정확히 20분 Run`이라고 약속할지는 실제 Vertical Slice 측정 후 결정한다.

#### 4세그먼트 의미

1. 제1 공세 · 지부 즉각 생존 / 유파 거울상 첫 조우.
2. 제2 공세 · 주변 전선 유지.
3. 제3 공세 · 반격 / 공세 근원 접근.
4. 제4 공세 · 최종 공세 / Run 최종 보스.

첫 3세그먼트는 5분 전후를 비슷한 예산으로 맞추고, 제4 최종 보스는 기억성 때문에 약간 긴 overtime을 허용할 수 있다. 다만 최종전만 3~5분 추가되어 전체 템포를 무너뜨리지 않도록 한다.

### B · 현행 runtime처럼 5:00 일반전 종료 후 보스 등장

```text
0:00~5:00 일반전
5:00 Boss 등장
Boss 처치 후 RESULT
```

장점:
- 현행 StageFlowController 구조와 가장 가깝다.
- `5분 생존 → 보스` 문구가 직관적이다.

문제:
- 보스 TTK가 각 세그먼트에 추가된다.
- 4세그먼트일 경우 active combat이 약 20분이 아니라 24~28분 이상으로 늘어나기 쉽다.
- Workbench까지 포함하면 실제 Run은 더 길어진다.
- 기존 DEC-005의 `약 20분 / 4×5분` 약속과 가장 크게 충돌한다.

### C · 보스를 4분대에 등장시키고 정확히 5:00까지 처치하지 못하면 실패

장점:
- Run 길이를 정확하게 통제할 수 있다.
- 밸런스 지표가 매우 명확하다.

문제:
- 사실상 DPS 체크가 되어 봉마의 준비형, 천술의 반응 누적형 같은 스타일에 불공정할 수 있다.
- 보스 패턴을 읽는 재미보다 시간 압박이 우선된다.
- 공간/빌드 판단보다 수치 최적화가 강제될 위험이 있다.

현재 비채택 권장.

## 벤치마크 적용 원리

- `20 Minutes Till Dawn`처럼 생존 시간 자체가 명확한 전투 목표가 되는 장점은 참고한다.
- `Brotato`처럼 전투 웨이브와 웨이브 사이 상점/판단 시간을 분리하는 원리를 참고한다.
- 닌자의 신에서는 이를 `active combat clock 약 20분 + Workbench/Fate 판단 시간 별도`로 변형한다.

## 적대적 검토

### 1 · 20분 약속 왜곡

문제: Workbench 시간을 제외하면 사용자 체감 Run은 20분보다 길다.

대응: 내부 명칭을 우선 `약 20분 전투 시계`로 사용하고, 실제 제품 카피는 Vertical Slice의 wall-clock P50/P90을 측정한 뒤 확정한다.

### 2 · Boss overtime 악용/지연

문제: 무제한 overtime이면 매우 방어적인 빌드가 지나치게 오래 버틸 수 있다.

대응: 하드 즉사 타이머보다 보스의 자연스러운 `잠식 고조`가 시간이 갈수록 압박을 올리게 한다. 이 강화도 회피 가능성을 없애지 않는다.

### 3 · 보스가 너무 일찍 느껴질 위험

문제: 4:30 등장하면 플레이어가 `5분 보스`라고 인지하지 않을 수 있다.

대응: UI/기획 문구는 `5분대 보스 결산`으로 표현하고, 경고→등장→처치가 5분 부근에 걸치도록 한다. 정확한 4:30은 초기 튜닝 시작값이지 영구 수치가 아니다.

### 4 · Elite와 Boss 간격 부족

문제: 3분 엘리트가 오래 살아남으면 보스 준비 시간이 사라진다.

대응: Elite는 20~35초 안팎의 중간 시험을 목표로 하고, 45초 이상 자주 걸리면 HP/증원 예산을 낮춘다. Elite가 살아 있는 상태에서 Boss를 강제 중첩시키지 않는 것을 기본으로 한다.

### 5 · 현행 코드 충돌

현재 `StageFlowController`는 `segment_duration_seconds = 300`, 시간 0에서 BOSS 요청, `segment_index >= 3`에서 COMPLETE다. 승인 시 구현 계획에서 반드시 다음을 별도 migration으로 다룬다.

- 3 → 4세그먼트.
- 일반 COMBAT와 Elite/Boss 이벤트의 세그먼트 내부 시점화.
- 300초 종료 후 Boss spawn 구조를 `4분대 Boss entry + soft overtime` 구조로 변경.
- RESULT/SHOP(Workbench)/FATE 동안 active combat clock 정지.
- 기존 MVP-0~3 테스트를 새 cadence 계약에 맞춰 의도적으로 갱신하되, 구현 전에는 현재 runtime을 수정하지 않는다.
