## DEC-2026-08-20-007 · 패배 = 전투불능/후퇴 + 최소 서사화

상태: `APPROVED_BY_USER_2026-08-20`

### 승인된 핵심

- HP 0 또는 Run 실패를 플레이어의 확정 사망으로 해석하지 않는다.
- 패배는 **이번 방어/출격에서 전투불능이 되어 후퇴하거나 구조된 실패**로 처리한다.
- 시간 회귀, 부활 비술, 동일 사건의 정사적 무한 반복을 세계관 코어에 새로 추가하지 않는다.
- 게임플레이에서는 Run을 다시 시작할 수 있지만, 모든 실패 Run을 세계관 연표에 1:1로 강제 설명하지 않는다.
- 정사적 무게는 주요 성공, 지부 생존, 전선 안정, 최종 평정과 플레이어가 만든 전설에 둔다.

```text
공세/출격 실패
→ 전투불능 또는 후퇴
→ 이번 Run 종료
→ 지부에서 재정비
→ 새 Run
```

### 플레이어 경험 목표

- 패배는 `죽음의 초월 능력`을 보여주는 장면이 아니라 **아직 전설이 되지 못한 닌자의 한계와 재도전**으로 느껴져야 한다.
- 새 Run은 같은 주인공의 재도전으로 읽을 수 있어 캐릭터 애착과 유파 정체성을 유지한다.
- 패배 설명은 짧고 기능적이어야 하며 전투 재시작 속도를 방해하지 않는다.

### 명시적 비채택

- `시간 되감기 / 루프를 기억하는 세계`를 기본 코어로 추가하지 않는다.
- `죽을 때마다 다른 닌자가 이어받는 영구 세대교체`를 현재 기본 구조로 채택하지 않는다.
- 패배할 때마다 긴 컷신·대사·부상 관리 시스템을 요구하지 않는다.

### 장기 재검토 후보

- 여러 닌자의 전승/희생을 강조하는 세대교체 구조는 장기 내러티브 확장 후보로 보존하되, 주인공 연속성보다 명확히 더 큰 플레이어 가치를 제공한다는 증거가 있을 때만 재검토한다.

### 벤치마크 원리 수준 참고

- `Hades`처럼 반복 실패를 완전히 세계관 규칙으로 만드는 방식은 불멸/귀환을 코어로 설계한 작품에 적합하다. 닌자의 신에는 같은 초자연 규칙을 복제하지 않는다.
- 일반 survivor/roguelite의 빠른 retry 원리는 참고하되, 패배 서사 설명이 전투 재진입보다 커지지 않게 한다.

## DEC-2026-08-20-008 · 닌자소울 = 전승의 불씨 / 수평 메타 성장

상태: `APPROVED_BY_USER_2026-08-20`

### 세계관 정의

- `닌자소울`은 적에게서 추출하는 문자 그대로의 영혼이나 죽은 닌자의 혼백이 아니다.
- 생사를 넘나드는 전투와 선택에서 쌓인 **의지·기량·깨달음·전승이 남긴 불씨**를 게임적으로 표현한 메타 자원이다.
- 패배 Run도 완전히 무의미해지지 않으며, 전투 경험과 발견의 일부가 전승으로 남을 수 있다.
- DEC-007의 전투불능/후퇴 해석과 충돌하지 않는다. 닌자소울을 얻기 위해 플레이어가 죽어야 할 필요가 없다.

```text
Run의 전투/선택/발견
→ 전승의 불씨가 남음
→ 닌자소울 획득
→ 무너진 지부의 전승 복구
→ 다음 Run의 선택 가능성 확대
```

### 메타 성장 원칙

핵심 규칙은 **`Run의 힘은 Run에서 만든다. Meta는 정답을 강하게 만드는 것이 아니라 더 많은 닌자 방식을 열어 준다.`** 이다.

닌자소울의 우선 사용처:

- 새로운 인법 후보 풀 해금
- 새로운 장비 후보 풀 해금
- 새로운 가방 후보 풀 해금
- 유파별 시작 선택/변형 해금
- 새로운 조합 발견 가능성 또는 관련 힌트 해금
- 적/보스/인법/조합 기록과 도감 정보
- 반복 플레이 편의 기능
- 새로운 도전 조건/변형 규칙
- 지부의 시각적 전승 복구

### 지부 복구의 역할

- 메타 진행은 별도 추상 메뉴만으로 끝내지 않고 **무너진 닌자 지부가 조금씩 전승 거점으로 되살아나는 시각 변화**와 연결한다.
- 복구 후보: 기록실, 수련장, 공방, 비전고, 작전지도, 전승비 등.
- 이들은 복잡한 건설/경영 시스템이 아니라 해금 상태를 읽기 쉽게 표현하는 거점 기능/시각 레이어다.
- 플레이어가 직접 벽을 짓거나 재료를 운반하는 기지건설 루프를 추가하지 않는다.

### 영구 수치 성장 제한

- 공격력/체력 같은 기본 전투 수치를 반복 구매해 크게 누적시키는 구조는 닌자소울의 주 성장축으로 두지 않는다.
- 소규모 접근성/온보딩 보정이 필요할 수는 있으나, 메타 수치가 Run 빌드의 공간·조합 판단을 압도하지 않아야 한다.
- 장기 플레이에서 `메타 수치가 충분히 높으면 빌드 품질이 중요하지 않다`는 현상이 나타나면 실패로 본다.

### 벤치마크 원리 수준 참고

- `Vampire Survivors`의 Run 밖 영구 업그레이드처럼 **실패해도 진척이 남는 만족감**은 참고한다.
- `Hades`의 영구 Talent처럼 **새 플레이스타일과 빌드 선택을 열어 주는 메타 진행**은 참고한다.
- 닌자의 신에서는 이를 강한 수치 인플레이션보다 **전승 복구 + 수평적 선택지 확장**으로 변형한다.

### 장기 적합성 / 재검토 조건

- 첫 반복 플레이에서 새 Run의 변화가 너무 약해 동기가 떨어지면 해금 빈도·시작 선택·도감/힌트 보상을 먼저 강화한다.
- 반대로 해금 후보 풀이 커져 원하는 빌드를 만들기 어려워지면 ban/favorite/유파 가중치 같은 선택 풀 제어를 검토한다.
- 영구 전투 수치 증가는 수평 성장만으로 초반 반복 피로를 해결할 수 없다는 플레이테스트 증거가 있을 때만 제한적으로 재검토한다.

## DEC-2026-08-20-009 · 4유파 공동 변방 전선 지부

상태: `APPROVED_BY_USER_2026-08-20`

### 승인된 핵심

- 게임의 무너진 지부는 특정 한 유파의 전용 본거지가 아니라 **네 유파가 공동으로 운용하던 변방 전선 지부**다.
- 이 지부는 네 유파가 완전히 화합해서 만든 상징적 연합 본부가 아니라, 봉인·요괴 출몰·주요 관문·교통로·국경/전선처럼 **어느 한 유파가 독점해서는 곤란한 위험 지역**을 공동 감시하기 위한 실무 거점이었다.
- 각 유파는 소수의 닌자와 전승/도구 일부를 파견해 지부를 유지했다.
- 전란이 격화되고 본부 지원이 끊긴 뒤 금지 인법·요괴·적대 세력의 공세가 겹치면서 지부가 거의 붕괴했다.
- 플레이어는 이 공동 지부에 남아 싸우는 네 유파 중 한 유파 출신의 아직 미완성인 닌자다.

```text
4유파 공동 변방 전선 지부
→ 전란 심화 / 지원 단절
→ 금지 인법·요괴·적대 세력의 연속 공세
→ 지부 붕괴
→ 플레이어가 선택한 유파의 방식으로 생존
→ 닌자소울로 공동 전승을 조금씩 복구
```

### 4유파 흔적과 메타 성장 연결

- 지부 폐허에는 네 유파의 흔적이 모두 남아 있을 수 있다.
- 예시: 봉마류 결계실/소환 흔적, 천술류 인법 기록, 귀인류 수련장, 흑영류 정보·암호 기록.
- 닌자소울을 사용해 지부 기능을 복구하는 행위는 **사라진 네 유파의 전승을 다시 이어 붙이는 과정**으로 읽힌다.
- 이를 통해 하나의 공용 지부 아트/UX를 유지하면서도 유파별 해금·NPC·기록·비주얼 차이를 부분적으로 표현할 수 있다.
- 유파 선택에 따라 지부 전체를 4세트로 교체하지 않는다.

### 「닌자의 신」 전설과의 관계

- 현재 지부 자체를 옛 「닌자의 신」의 본거지나 신전으로 고정하지 않는다.
- 다만 이 지역은 오래전부터 전략적·영적 중요성이 있었고, 지부나 주변 폐허에 **「닌자의 신」 전설과 관련된 낡은 기록·비석·구전의 흔적**이 남아 있을 수 있다.
- 그 흔적은 플레이어를 선택받은 후계자로 지명하지 않는다. 전설은 절망 속에서 스스로 붙잡는 상징으로 남긴다.

### 제작 범위 / 보호

- 네 유파별 전용 지부 4세트를 만들지 않는다.
- 유파 선택 때문에 메타 거점의 핵심 기능·동선·Workbench를 복제하지 않는다.
- 공동 지부를 정치/외교/세력 경영 게임으로 확장하지 않는다.
- 기존 4유파 전투 감정, MVP-0~3, MVP-4 Workbench/백팩, DEC-008 수평 메타 성장 원칙을 유지한다.

### 장기 적합성 / 재검토 조건

- 유파 정체성이 지부에서 너무 희미하게 느껴지면 전체 거점을 교체하기 전에 `유파 전승 코너`, 유파별 NPC/기록/장식, 시작 선택 연출을 강화한다.
- 장기 콘텐츠 확장에서 다른 지부나 유파 본거지를 방문할 수 있으나, 첫 제품의 메타 허브는 공동 변방 전선 지부로 유지한다.

### 벤치마크 원리 수준 참고

- 여러 역할/빌드를 하나의 공용 거점에서 관리하고 반복 플레이에 따라 그 장소가 변하는 **공용 허브 + 메타 진척 시각화 원리**만 참고한다.
- 외부 작품의 건물 구조, NPC, 세계관, 거점 이름이나 업그레이드 방식을 복제하지 않는다.
