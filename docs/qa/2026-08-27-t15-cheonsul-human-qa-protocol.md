# T15 · 천술류 Human QA 프로토콜

## 목적과 판정 경계

이 프로토콜은 T14 천술류 release-near 세로 슬라이스를 실제 사람이 플레이해, 남은 세 유파를 생산하기 전에 공용 전투·진행·Workbench 골격의 문제를 찾기 위한 것이다.

자동화가 증명하는 것은 도메인 순서와 UI 계약뿐이다. 다음 항목은 참가자의 직접 답변 또는 직접 관찰 기록 없이는 `PASS`가 될 수 없다.

- 첫 30초 천술류 정체성
- Core → Elite → Trace → Boss 긴장 곡선
- 공격/상태 신호의 공정성
- Trace의 목적과 회수 행동
- Boss-clear Workbench의 의미
- 백팩·경로·운명 판단 가치와 피로
- 한국어 문구/배치 가독성
- mouse, keyboard/gamepad-focus, touch의 실제 핵심 완료 경로

T14의 의도된 한계도 판정에서 분리한다. Workbench의 보스 보상은 후보를 읽는 것까지만 가능하고, 보상 선택·배치·Fate/경로 확정은 자동으로 일어나지 않으며 현재 화면에서 완료할 수 없다. 이는 T15 실패로 기록하지 않는다. 다만 플레이어가 이 한계를 명확히 이해하는지는 평가한다.

## 고정 환경

- 기준 리비전: `main` `977158acce4dd7cd27eb82d9ae3699673f4e1029`
- 엔진: Godot 4.7.1
- 시작 씬: `res://scenes/main/main_scene.tscn`
- 기본 선택: 천술류
- 테스트 중 보스·Elite·Trace 시간을 임의로 건너뛰지 않는다. 시간 단축은 도메인 자동 검증에만 쓰며 긴장 곡선의 사람 판정을 대체하지 않는다.
- 진행자는 유파 기능을 미리 설명하지 않는다. 질문은 해당 신호가 먼저 나타난 뒤에만 한다.
- 유파 선택 화면의 `기능 도움말`은 실제 구현된 기능만 설명하는 보조 수단이다. 30초 정체성 판정은 도움말을 열지 않은 첫 실행으로 먼저 기록하며, 도움말 사용성은 그 뒤 별도 실행에서 판정한다.

## 관찰할 실제 신호

| 구간 | 사람에게 보일 신호 | 기대 이해 |
| --- | --- | --- |
| 시작 | `천술류: 원소 반응을 준비하세요.`와 선택 화면의 “속성 상태를 겹쳐 반응을 터뜨린다” | 상태를 순서대로 겹쳐 반응시키는 유파라고 예상한다. |
| Core | 불 장판, `BURN`/`WET`/`SHOCK` 배지, `WET + SHOCK`, 반응 게이지와 `오행폭주` | 보이는 상태 조합이 추가 효과와 궁극기로 이어진다는 것을 읽는다. |
| Elite | 정예 경고/정예 안내와 전투 전환 | 일반 압력과 다른 중간 목표가 왔음을 안다. |
| Trace | 상자 토큰·흔적 안내, `Enter로 회수하세요.` | 흔적이 자동 전투 버프가 아니라 다음 Boss 접근을 여는 행동임을 안다. |
| Boss | 보스 경고와 Boss 안내 | Trace 회수와 시간 조건 뒤의 별도 위협이라고 읽는다. |
| Workbench | 보스 보상 후보, 임시 다음 유파/운명, 비활성 `작업대 확정`과 이유 | 현재 선택은 임시이며 보상 선택·배치가 남아 자동 확정되지 않았음을 안다. |

## 세 입력 경로

각 경로는 실제 사람이 하나의 유효 선택을 완료하고, 그 즉시 화면의 상태 변화가 보이는 것으로 확인한다.

| 경로 | 실행 | 최소 완료 관찰 |
| --- | --- | --- |
| Mouse | 천술류 선택 버튼을 클릭하고 Workbench에서 다음 유파 카드와 운명 후보를 각각 클릭한다. | 선택 카드에 `임시 선택`이 표시되고 확정 버튼은 보상 대기 때문에 계속 비활성이다. |
| Keyboard/gamepad-focus | 시작에서 `2`로 천술류를 고르고, Trace가 나타난 뒤 `ui_accept`에 매핑된 확인키를 눌러 회수한다. Workbench에서는 포커스 이동 후 확인으로 카드 하나를 고른다. | Trace 회수 안내가 다음 Boss 경고로 전환되고, 포커스 선택은 한 번만 의도를 낸다. |
| Touch | 실제 터치 가능 화면에서 천술류 버튼과 Workbench의 유파/운명 카드를 탭한다. | 탭 한 번이 한 의도만 내며, 카드와 한국어 상태 문구를 읽을 수 있다. |

도움말은 네 유파의 선택 버튼마다 분리되어 있다. 열어도 유파가 선택되지 않으며, `닫기` 또는 `ui_cancel`로 돌아온 뒤에만 숫자 선택을 다시 받는다. Mouse와 touch에서는 도움말 버튼과 `닫기` 버튼을 각각 한 번씩 눌러 같은 경계를 확인한다.

가상 `InputEventScreenTouch` GUT은 회귀 보호 근거일 뿐 실제 터치 경험의 대체물이 아니다.

## 참가자 진행 스크립트

1. 참가자에게 “설명 없이 시작해 보세요. 조작 중 이해되지 않는 점은 소리 내어 말해 주세요.”라고만 안내한다. 첫 실행에서는 기능 도움말을 열지 않는다.
2. 천술류를 고른 뒤 첫 30초를 플레이하게 한다. 진행자는 이때 조작을 돕지 않는다.
3. 30초 직후 묻는다: “이 유파는 무엇을 준비해서 어떤 결과를 내는 게임이라고 보였나요?” 답에 `상태`, `원소`, `순서`, `반응` 중 둘 이상이 자발적으로 나타나는지 기록한다.
4. Core 전투에서 WET와 SHOCK 또는 반응 신호가 나타난 뒤 묻는다: “방금 무엇이 겹쳐서 강한 결과가 났다고 보였나요?” 답과 화면 신호의 시점을 기록한다.
5. Elite 경고부터 Trace 회수까지 자연 진행을 관찰한다. Trace 신호가 나타난 직후 “지금 무엇을 해야 하며, 그 행동은 무엇을 여나요?”라고 묻는다. 플레이어가 `확인/Enter`, `Boss`, `다음 단계`의 관계를 설명하는지 기록한다.
6. Boss 경고와 Boss 전투를 거쳐 Workbench에 도달한 뒤, 보상 후보·다음 유파·운명 중 먼저 주목한 것을 기록한다. 그 다음 “지금 무엇이 임시이고, 무엇을 하면 다음 전투가 확정될까요?”라고 묻는다.
7. Workbench에서 유파 카드와 운명 후보를 고르게 한다. 그 뒤 “이 선택이 다음 전투에 어떤 차이를 만들 것 같나요?”와 “원하는 결정을 내리기 전, 조작 때문에 멈춘 순간이 있었나요?”를 묻는다.
8. 첫 실행이 끝난 뒤 별도 실행에서 기능 도움말을 열어, 설명이 실제 보인 기능과 일치하는지와 `닫기` 후 선택이 의도대로 가능한지를 묻는다. 이 결과는 30초 무설명 정체성 판정을 대체하지 않는다.
9. 입력 경로별 최소 완료를 시행하고, 터치 장비가 없으면 `TOUCH_NOT_RUN — physical touch hardware unavailable`로 기록한다. 가상 터치 테스트로 바꾸지 않는다.
10. 마지막으로 “가장 흥미로웠던 선택 하나와, 불공정하거나 답답했던 순간 하나”를 묻는다.

## 판정 규칙

- `PASS`: 참가자의 답과 직접 관찰이 목표 관계를 지지하며, 진행자의 사전 설명이 필요하지 않았다.
- `UNCLEAR`: 관계를 말하지 못했거나 답과 화면 신호가 모순됐다. 반복 세션 또는 공유 골격 수정 후보이다.
- `FAIL`: 진행을 막는 오류, 예상과 반대되는 상태 변화, 읽을 수 없는 핵심 문구, 또는 동일 입력의 중복/누락 동작이 재현됐다.
- `GOOD_DEPTH`: 배치·경로·운명의 기회비용을 비교하는 고민이다.
- `BAD_FRICTION`: 원하는 행동이 분명한데 조작, 시각 배치, 문구 또는 상태 불명확성 때문에 지연된다.

한 세션이라도 `FAIL`이면 T15는 통과가 아니다. `UNCLEAR`는 원인과 재검증 계획이 문서화될 때까지 다음 유파 생산을 열지 않는다. 실제 사람의 답이 없는 항목은 `NOT_RUN`이며 자동 테스트 성공으로 승격할 수 없다.
