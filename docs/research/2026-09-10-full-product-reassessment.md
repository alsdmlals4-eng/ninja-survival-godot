# 닌자의 신 — 전면 재검토와 재기획 제안

검토일: 2026-09-10 · 1차 공개자료 기반 재검토 · 상태: **RESEARCHED / PROPOSED — 새 제품 방향 미확정**

## 1. 결론부터

기존 게임을 전부 버릴 이유도, 기존 구성을 그대로 지킬 이유도 아직 없다. 권장하는 방향은 **자동전투와 공간 빌드를 하나의 플레이 경험으로 묶는 것**이다. 다만 이는 기존 장르를 기정사실로 유지한 결론이 아니라, 아래 세 장르 대안과 15개 게임의 공개 자료를 비교한 뒤 가장 먼저 검증할 가설이다.

가장 중요한 발견은 “자동전투 + 가방 정리”가 이미 존재하는 조합이라는 점이다. God Of Weapons는 자동 공격·회피·제한된 인벤토리 배치를 명시하고, Backpack Survivor도 이동 중심 자동전투와 가방 관리를 내세운다. 따라서 닌자 외형과 유파 이름만 붙이는 것으로 독창성을 주장하면 안 된다.[^1][^2]

새 방향의 차별화 후보는 **“가방에서 인법의 관계를 바꾸면, 전장에서 좋은 이동 경로도 달라진다”**이다. 공간 빌드가 단순 공격력 계산판을 넘어 플레이어의 행동을 바꾸는지 검증한다. 반대로 이것이 설명 부담만 늘린다면 연결 규칙을 축소하거나, 가방 중심 전술형으로 방향을 바꾼다.

이번 승인 범위는 장르·기획·기존 요소 전체의 재평가다. 아래 유지·수정·삭제는 모두 **권고안**이며, 현재 실행 게임·저장 데이터·승인 자산을 이미 변경했다는 뜻이 아니다. 기존 이미지들은 새 제작의 참고자료로만 사용한다. 새 기획의 최종 승인, 신규 아트 확정, 런타임 연결은 구분한다.

## 2. 검토 범위와 판단 기준

### 무엇을 결정하기 위한 조사인가

1. 이동 자동전투, 수동 액션, 준비형 전술 중 어떤 핵심 행동을 중심에 둘 것인가?
2. 가방·유파·조합은 서로 다른 고민을 만드는가, 같은 보상을 여러 번 선택하게 만드는가?
3. 흔적·운명·전장 순서가 선택인가, 다음 화면으로 가는 절차인가?
4. 닌자·요괴·인법이라는 소재가 실제 조작과 피드백에서 드러나는가?
5. 새 이미지와 모션을 반복 생산하고 Godot에 연결할 수 있는가?

판단 기준은 핵심 재미 기여, 결과의 가독성, 반복 선택의 변화, 소재와의 정합성, 비교작과의 차이, 제작·검증 비용, 접근성, 실패 후 복구다. 임의의 합산 점수나 판매량 추정으로 결론을 포장하지 않는다.

### 증거의 범위

- **저장소 사실:** 현재 채택된 규칙과 실제 코드·씬의 일부 핵심 소비처를 직접 확인했다. 전체 코드에 대한 기능 감사나 새 게임 실행 검증은 아니다.
- **공식 제품 사실:** 개발사·배급사 공식 상점 설명을 중심으로 15개 게임을 비교했다. 아래 사실 칸은 공개 설명에 근거하며 내부 알고리즘 역공학 결과가 아니다.
- **실무 근거:** 개발자 인터뷰·개발사 회고성 공지와 엔진·도구·접근성 공식 문서를 읽었다. 업계 관계자에게 새 인터뷰를 실시한 것은 아니다.
- **반응 근거:** 구체적인 긍정·부정·혼합 자기보고 사례를 확인했다. 편의 표본이며 모집단의 빈도나 인과를 증명하지 않는다.
- **미실시:** 비교 게임 직접 조작, 체계적 리뷰 코퍼스 분석, 신규 게임 플레이테스트, 판매 예측, 법률상 독창성 판단, 신규 아트/모션 제작 및 런타임 검증.

상점과 검색 캐시는 날짜·언어·리뷰 집계가 서로 다를 수 있다. 가격·리뷰 수·현재 판매량은 설계 근거로 쓰지 않는다. 개발자 발언 역시 성공 원인의 실험적 증명과 구분한다.

## 3. 출발점: 기존 요소 중 실제로 있는 것

| 요소 | 현재 확인한 상태 | 재검토에서의 의미 |
|---|---|---|
| 플레이어 | CharacterBody2D, 별도 시각 노드·그림자·카메라 | 위치·판정과 표현의 분리는 재사용 후보 |
| 모션 | PlayerVisualController가 이동/피격 텍스처를 교체 | 프레임 애니메이션 완성 상태가 아님 |
| 기본무기 | 일본도 근접 판정과 수리검 투사체가 별도로 자동 실행 | 수동 액션으로 전환하면 입력·판정·애니메이션 계약 재설계 필요 |
| 군중 | WaveSpawner의 기본 최소 10, 거리 범위와 배치 단위 스폰 | 풍부한 군중의 기반이지 난이도·성능 검증은 아님 |
| 가방 | 6×6 기술 보드, 시작 가방 3×3 | 출발 면적과 기술 상한을 분리해서 평가 |
| 인술 | 4유파 × starter/elite_scroll/boss_scroll = 12 정의 | 개수보다 실제 전술 차이를 평가할 대상 |
| 스테이지 | Core→Elite→Trace→Boss 상태와 경고 게이트 | 진행을 소유하는 구조는 재사용 가능, 단계 수는 재평가 |
| 준비 단계 | 공간 배치·조합·운명·다음 경로의 확정 경계 | 데이터 무결성과 플레이어가 보는 화면 수는 별개 |
| 메타 | 닌자소울과 각성·도감의 기존 기획/구현 기록 | 반복 동기의 후보, 새 성장 곡선의 검증은 아님 |

주의할 실제 차이: StageEncounterState는 기본값으로 보스 출현 하한 270초를 두지만 외부 타이밍 설정을 받는다. 기존 “약 5분” 문구를 모든 설정의 정확한 실측 시간으로 쓰지 않는다. 엘리트 처치 후 흔적 미회수 상태에서는 일반 스폰을 중지하고 회수 후 재개한다. 따라서 “언제나 최소 10마리”라는 표현도 전체 페이즈의 불변 규칙은 아니다.

기존 사람용 블루프린트는 이미 “가방으로 인법을 조립한다”는 약속을 담고 있다. 새로 필요한 것은 같은 슬로건의 재작성보다 **어떤 배치를 바꾸면 어떤 행동이 달라지는지 보여주는 증거**다.

## 4. 15개 게임 비교: 원리만 가져오고 표면은 복사하지 않는다

아래의 적용과 실패 위험은 프로젝트 분석이다. 각 게임의 실제 결함이나 판매 원인으로 단정하지 않는다.

### 비교 후 남는 판단

자동전투의 약점은 조작 수가 적다는 사실 자체가 아니다. 이동 위치를 바꿔도 결과가 별로 달라지지 않거나, 빌드가 무엇을 바꾸는지 보이지 않을 때 수동적으로 느껴질 가능성이 있다. 반대로 수동 공격은 행동의 인과를 직접 만들지만 새로운 모션·입력·밸런스 비용을 요구한다. 어느 쪽이 더 재미있는지는 새 제품의 플레이 증거로 판단해야 한다.

가방은 이미 여러 제품이 사용하는 장르 관습을 참고할 수 있지만, 공간을 채우는 재미와 전투를 바꾸는 재미는 별개다. 아이템을 90도 돌리는 행위가 단순히 빈칸을 메우는 일인지, 버리고 남길 것을 선택하게 만드는지 분리해 검증한다.

## 5. 실무 사례와 사용자 반응에서 얻는 교정

### 제작자·공식 자료

**단순한 기반은 제작 전략일 수 있다.** Vampire Survivors 제작자는 조작을 단순화한 이유 중 하나로 쉽게 완성할 기반을 만들고 좋아하는 콘텐츠 제작에 시간을 쓰려 했다고 설명했다. 우리에게 적용할 것은 그 게임의 수치가 아니라, 자주 반복되는 기반을 작게 유지하는 원리다.[^16]

**기술 테스트와 제품 경험은 다르다.** Supergiant는 Hades II의 제한된 기술 테스트를 호환성 문제 탐지용으로 설명하고, 피드백 시점은 알려진 미완성 사항만 지적받지 않으면서도 수정할 수 있을 만큼 이른 때여야 한다고 밝혔다. 따라서 회색 상자 테스트로 재미를 승인하지 않고, 반대로 네 유파 전체를 만든 뒤 처음으로 체감 검수를 하지 않는다.[^17]

**표현은 판정을 따라야 한다.** Godot 공식 자료는 개별 프레임/시트의 AnimatedSprite2D와 Sprite2D+AnimationPlayer를 모두 지원한다. 현재 단일 이미지 교체를 새 프레임군으로 바꾸는 길은 있지만, “시트를 만들면 기존 씬이 자동으로 애니메이션을 재생한다”는 가정은 틀리다.[^18]

**화려함보다 정보 보존이 먼저다.** Microsoft XAG는 중요 정보를 시각·청각 등 복수 경로로 전달하고 색만으로 구분하지 않을 것을 권한다. 유파색 외에 모양·움직임·효과음으로 적/아군·준비/발동/종료를 구분한다. 이는 접근성 완료 판정이 아니라 새 제작의 검사 항목이다.[^19]

**도구는 제작 계약을 대신하지 않는다.** Aseprite는 프레임·레이어·시트·JSON 내보내기를 제공한다. 그러나 로컬 연결 도구의 허용 기능은 별개이고, Godot가 그 JSON을 자동 소비한다고 단정할 수 없다. 프레임 메타데이터의 실제 변환·소비처를 검증해야 한다.[^20]

### 긍정·부정·혼합 반응의 작은 탐색 표본

| 표본 | 자기보고 내용 요약 | 무엇을 조사할 계기가 되는가 | 한계 |
|---|---|---|---|

## 6. SWOT와 실제 대응

- **SO:** 공간 빌드의 기존 기반으로 “조합 전/후 이동 방식이 달라지는 한 장면”을 만든다.
- **WO:** 익숙한 생존 조작은 활용하되, 기존 복잡한 용어를 학습 순서에 따라 공개한다.
- **ST:** 요괴·전승을 색 스킨이 아니라 패턴과 대응 방식으로 표현한다. 시장 전체에 없다는 주장 대신 우리 실행의 차이를 제시한다.
- **WT:** 전 유파·보스·상점 UI·메타를 동시에 새로 만드는 것을 보류한다. 가장 작은 대표 경험이 실패하면 나머지 제작비를 쓰지 않는다.

기회는 수요 규모를 검증했다는 뜻이 아니다. 비교작의 존재는 경쟁과 비교 기대의 증거이지, 이 프로젝트의 구매 의향 증거가 아니다.

## 9. 독창성과 창의성: 무엇을 새롭게 만들 것인가

### 권장 가설: 인법을 조립하고, 몸으로 완성한다

가제 한 문장: **“인법서를 배치해 나만의 기술 연결을 만들고, 요괴 군중을 원하는 자리로 끌어들여 한 번에 무너뜨리는 닌자 생존 게임.”**

대상 가설은 연타·복잡한 조준보다 이동 판단과 빌드 실험을 좋아하는 플레이어다. 플랫폼은 우선 기존 Windows 소비처에서 검증하되, 이것을 Android·터치 경로 폐기 승인으로 해석하지 않는다. 세션 길이·유료 판매 방식·시장 지역은 이 조사로 새로 확정하지 않는다.

새 규칙 후보 예시:

- **봉마 × 흑영: 유인과 처형.** 식신이 붙잡은 무리에 표식 공격이 집중되는 배치. 플레이어는 무작정 도주하기보다 식신 쪽으로 적을 유도할 이유를 얻는다.
- **천술 × 귀인: 준비와 돌파.** 미리 상태를 쌓은 적에게 근접 자동기술의 후속 효과가 연결되는 배치. 안전하게 도망가는 것과 짧게 접근하는 것 사이의 판단을 만든다.
- **같은 아이템, 다른 연결.** 하나의 인법서를 피해 증폭 옆에 둘지 대상 확장 옆에 둘지 선택한다. 전자는 강한 적 하나를, 후자는 몰린 적을 상대하기 좋게 한다.

위 예시는 신규 승인 기술명·수치·레시피가 아니다. 현재 12인술의 기존 의미와 데이터에 접목할 수 있는지 확인해야 한다. 연쇄 트리거나 연결 문법 자체도 Spell Disk·Nova Drift 등과 비교해야 하므로 세계 최초라고 주장하지 않는다.[^12][^13]

추가 반증 검색에서도 Wandness가 부품 조합으로 투사체 행동을 바꾸는 생존 게임을 표방함을 확인했다. 이 사례 때문에 **“숫자가 아니라 기술 행동이 바뀐다”만으로도 차별화가 끝나지 않는다.** 우리의 후보는 그 변화가 닌자의 유인·접근·이탈 경로까지 바꾸는지에 초점을 둔다. 이것도 아직 독창성이 검증된 결과는 아니다. 검색 캐시마다 평가 집계가 달라 이 게임의 흥행/실패를 단정하지 않는다.[^26]

창의성의 검증 단위는 명칭이 아니라 **새로운 반복 선택**이다. “닮지 않은 그림”만으로 독창성을 판단하지 않고, 동일한 적·장비에서도 다른 이동/배치 결정을 만들었는지 본다. 경쟁작 UI·로고·캐릭터·수치·구체 레시피의 복제는 제외한다.

### 기능을 늘리지 않는 대안도 함께 유지

연결 트리거를 새로 만들지 않고 기존 인접 보너스의 전투 범위·타깃 설명과 피드백만 강화하는 안을 먼저 대조한다. 이것으로 충분한 인과와 재미가 나오면 새 연결 시스템은 추가하지 않는다. 새 시스템의 화려함이 기존 해법보다 낫다는 증거는 아직 없다.

## 10. 핵심 루프·난이도·학습의 재설계 가설

```text
전장 진입 → 군중의 빈틈/유인 경로 선택 → 자동 인법의 결과 확인
→ 짧은 변곡점과 보상 → 배치 변경과 결과 미리보기 → 다음 전투에서 차이 확인
→ 주요 적 공략 → 정산·각성/새 선택지 → 다른 빌드로 재도전
```

이 흐름은 기존 Trace/Fate를 이미 삭제한 새 정본이 아니라, 비교 실험용 간결한 후보 루프다.

| 규칙 후보 | 유도하려는 행동 | 기대 경험 | 반증 신호 |
|---|---|---|---|
| 배치가 공격 형태/대상 관계 변경 | 다음 전투에 맞춰 선택 | 내가 만든 인법이라는 소유감 | 선택 이유를 설명 못하고 빈칸만 채움 |
| 적의 위험도와 동시 발동 구분 | 큰 전조를 보고 공간 확보 | 많이 몰려와도 공정함 | 회피 공간이 없거나 원인을 모르는 죽음 |
| 강한 적 뒤 준비/회복 | 직전 실패 원인을 반영해 재배치 | 긴장 후 이해·성장 | 준비가 의무적인 메뉴 노동이 됨 |
| 소수 개념을 순서대로 체험 | 먼저 실행하고 결과를 관찰 | 설명 없이도 학습 | 팝업 확인만으로 다음 단계에 진입 |

순간 보상은 공격 발동→접촉→처치의 인과, 구간 보상은 새 배치의 변화, 회차 보상은 새 시도 가능성으로 연결한다. 여기서 DDD는 의학적 도파민 측정이 아니라 행동·피드백·보상 품질의 설계 언어다. 숫자·보상 팝업 밀도를 무조건 높이지 않는다.

난이도는 적 HP만으로 조절하지 않는다. 규칙 이해, 반응 속도, 동시 위협, 안전 공간, 회피 후 복구를 나눠 본다. 새 자동 난이도 조절기는 우선 추가하지 않는다. 고정된 비교 조건에서 배치 효과와 대응 가능성부터 확인한다. 색·사운드·형태의 복수 단서, 입력 재설정·설명 재열람·효과 강도 조절은 기술 테스트와 별개로 사람 사용성을 검수해야 한다.[^19]

## 11. 이미지·Aseprite·모션·동작을 한 번에 설계하는 방법

### 표현 방식 세 대안

| 방식 | 이점 | 부담 | 현재 판정 |
|---|---|---|---|
| 작은 전장 크기에 맞춘 페인터리 프레임 | 기존 소재 감성과 키아트의 연결 가능 | 프레임 사이 비례·접지·명암 일관성 검수 | 대표 1유닛 비교 후보 |
| 제한 팔레트 픽셀 프레임 | 작은 형태와 프레임 경계를 통제하기 쉬움 | 픽셀 단위 교정·스타일 재정의 필요 | Aseprite 때문에 자동 선택하지 않음 |
| 분리 파츠 기반 2D 리깅 | 일부 모션 재사용과 부드러운 보간 | 관절·가림·새 방향 실루엣·엔진 리그 비용 | 다수 방향/긴 모션이 필요할 때 비교 |

장르는 그림체를 강제하지 않는다. 이미지 모델로 원화/필요 프레임을 제작하고, Aseprite는 적합한 프레임 정렬·타이밍·레이어·내보내기에 선택한다. 도구의 공식 전체 기능과 현재 연결된 허용 기능을 혼동하지 않는다. 로컬 생성/메타데이터 프로브 성공은 제작 파이프라인 전체 성공이 아니다.[^20]

### 첫 제작 패키지에 필요한 연결

- 실제 전장 카메라 크기에서 플레이어/일반 적/강한 적의 크기 관계를 먼저 정의한다. 캔버스 해상도나 FPS를 임의로 확정하지 않는다.
- 상태: 대기, 이동, 대시, 피격, 사망. 적은 필요한 경우 준비→발동→회복을 포함한다. 모든 유닛에 같은 프레임 수를 강제하지 않는다.
- A안에서는 기본 공격 본체 모션을 의무 추가하지 않는다. 자동 무기 이펙트와 이동 모션을 독립시키고, 전투 이벤트와 발동 표현을 맞춘다.
- 발 기준점·바닥 그림자·피격 중심·시각 높이를 분리한다. 대시 잔상이나 상하 흔들림을 충돌 위치 이동으로 구현하지 않는다.
- 원본→후보 프레임→시트/메타데이터→Godot Resource→실제 씬 소비처를 추적한다. 사용자 승인 전에는 후보이며 기존 runtime binding을 덮어쓰지 않는다.
- 일반 적 한 종으로 두 번째 모션군도 반복 제작해 작업이 재현되는지 확인한 뒤 유파 전체로 확대한다.

| 책임 | 기존 기반 | 제안 검증 경계 |

현재 엔진 계열은 Godot 4.x이며 과거 실행 증거의 4.7.1은 현재 호스트 확인을 대신하지 않는다. 이번 문서 작업에서 엔진 업데이트·실행·플러그인 설치는 하지 않았다. 새 런타임 변경 시 정확한 프로젝트/에디터/엔진 신원을 다시 확인한다.

새 설계와 저장 구조가 달라지면 기존 파일을 파괴적으로 마이그레이션하지 않는다. 우선 별도 후보 씬/설정 또는 명시된 버전 경계에서 비교하고, 승인된 전환에서만 기본 소비처를 옮긴다. 어떤 기존 파일이 불필요해지는지는 참조와 복구 가능성을 확인한 뒤 결정한다. 전면 재검토는 대량 삭제 승인이 아니다.

## 13. 검증 순서와 다음 산출물

### 단계 1 — 방향 비교와 선택

이 보고서의 A/B/C 중 대표 경험 방향을 정한다. 지금은 A를 첫 검증 대상으로 추천하되, 신작 장르와 고유 연결 규칙을 확정하지 않았다. 공개 자료 기반 기술 가능성은 있으나 새 기능의 실행 검증은 없다.

### 단계 2 — 사람용 새 블루프린트

선택한 방향으로 다음을 하나의 사람용 원고에 연결한다: 한 줄 약속, 첫 전투 장면, 조작, 전투 전후 빌드 변화, 스테이지 여정, 실패·재도전, 메인/준비/도감의 와이어프레임, 플로우맵. 과거 PDF의 페이지 수를 목표로 삼지 않고 새 내용을 이해할 수 있는 장면을 우선한다. 기존 PDF는 참고 보존한다.

### 단계 3 — 짧지만 완성된 대표 구간

플레이어 1종, 일반 적 1종, 강한 적 1종, 구별되는 두 빌드, 배치 변경 1회, 보상·재도전까지 연결한다. 필요한 신규 이미지·모션·SFX·VFX·UI 상태를 함께 준비한다. 기술만 묻는 작은 실험과 재미를 묻는 완성형 구간은 구분한다.

| 검증 질문 | 비교 방식 | 기록할 것 | 결정 기준(실시 전 확정할 계획) |
|---|---|---|---|
| 배치가 행동을 바꾸는가 | 동일 적/장비의 기존 보너스 표현안 vs 연결 효과안, 한 변수씩 | 배치 이유, 이동 경로, 효과 설명, 다음 시도 의도 | 체감 차이가 없으면 새 연결 시스템 축소/보류 |
| 전투 흐름이 끊기는가 | 같은 총 전투량에서 준비 빈도만 변경 | 메뉴 소요, 반복 조작, 이탈·피로 자기보고 | 고민보다 정리 노동이 우세하면 화면/빈도 통합 |
| 닌자와 전조가 읽히는가 | 동일 장면에서 표현 방식만 비교 | 자기 위치 찾기, 위험 원인 설명, 접지·피격 위치 | 보이지 않는 피해/판정 불일치가 있으면 확대 중단 |
| 군중·연쇄가 감당되는가 | 적·이펙트 수를 단계적으로 올리는 기술 측정 | frame time 분포, 메모리, 충돌/대상 탐색 비용 | 목표 기기 예산 미정 상태에서 성능 PASS 금지 |
| 새 제작이 반복 가능한가 | 두 번째 유닛/모션군 제작 | 교정량, 축·발 정렬, 재수출/재연결 결과 | 첫 유닛 수동 성공만으로 파이프라인 완료 금지 |

사람 검증은 빌드·기기·사전 지식·과제·표본을 기록한다. 초기 소규모 관찰로 혼란을 찾을 수 있지만 통계적 우월성은 주장하지 않는다. 실측 전 목표 시간/FPS/성공률을 사후에 끼워 맞추지 않는다. 비용·모집이 필요한 외부 조사는 별도 범위를 정한다.

## 14. 이번 작업의 정본·학습·미검증 상태

- 이 문서는 연구와 제안의 owner이며 승인된 게임 규칙 owner를 대체하지 않는다.
- 사용자 승인 범위인 “전면 재검토, 기존 요소도 근거에 따라 활용”만 Decisions/Active Context/로드맵에 반영한다.
- 2026-08-30 기존 벤치마크는 기존 자동형·Trace·Fate를 보호하는 범위였다. 이번 문서는 그 경계까지 재평가하므로 옛 보고서를 덮어쓰지 않는다.
- Base의 컨셉 분석 방법을 프로젝트에 선택 적용했다. 새 전역 규칙·스킬·Base 계약 업그레이드는 하지 않는다.
- 학습: 직접 경쟁작 비교를 고유성 주장보다 앞에 둔다. 도구 연결 성공과 자산 제작/애니메이션/runtime 성공을 분리한다. 기존 화면 수와 데이터 무결성 구조를 혼동하지 않는다.
- 신규 게임/아트/저장/밸런스 변경 없음. 기계·runtime·사람·기기·출시 검증은 이번 새 설계에 대해 **NOT_RUN**.
- 남은 핵심 위험: A안의 실제 차별성, 설명 부담, 반복 모션 제작 비용, 군중 성능, 목표 사용자·기기·세션 길이의 확정, 체계적 사용자 반응 조사.

### 연구 패키지 검토 기록

각 회차는 요청 범위·기존 사실·외부 근거·대안·제작성·권한·미검증 경계를
전체적으로 다시 대조했다. 아래는 주된 발견이며 분할 영역만 검사했다는 뜻은 아니다.
이는 단일 작성자의 문서 검토로, 독립 전문가나 사람 플레이 검증을 대체하지 않는다.

| 회차 | 주된 공격과 판정 | 교정/재검증 |
|---|---|---|
| 1 | 기존 연구가 자동형·Trace·Fate를 보호하므로 전면 재검토를 대표하지 못함 | 별도 새 연구 owner, 기존 보고서 보존과 새 권한 범위 명시 |
