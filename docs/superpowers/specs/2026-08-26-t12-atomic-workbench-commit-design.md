# T12 원자적 Workbench 확정 설계

> 승인 근거: 사용자가 2026-08-26에 새 T12 이슈/브랜치로 진행을 승인했다. 기존 PR #49는 읽기 전용 참고 자료다.

## 목표

Workbench에서 고른 최종 백팩 스냅샷, 정확히 하나의 Fate, 임시 다음 학교를 하나의 도메인 경계에서 함께 확정한다. 하나라도 준비되지 않았으면 세 확정 소유자는 모두 기존 상태로 남는다.

## 범위와 제외

- 포함: `RestBackpackSession`, `FateController`, `RunBuildState`, `RunRouteState` 사이의 최소 조정자와 단위 GUT 계약.
- 제외: `MainController`, Scene/UI, 입력, 전투/조우, 저장/메타 시스템, 이미지·에셋, 기존 PR #49 수정.

## 선택한 접근

1. **권장 — 사전검증 조정자:** 보류 Fate와 세션/경로의 읽기 전용 상태를 먼저 점검하고, 이미 유효하다고 증명된 세 확정 호출만 실행한다. 조정자는 REST가 진행 중인 동안 동일 소유자 묶음에 고정된다.
2. 보상 트랜잭션에 Fate/경로를 흡수: 기존 보상 책임을 침범하고 T07/T11 회귀 위험이 커져 거절한다.
3. UI가 세 소유자를 차례로 호출: 화면 순서가 도메인 원자성을 소유하게 되어 T13을 선행시키므로 거절한다.

## 구성과 데이터 흐름

`FateController`는 후보 중 하나를 **보류**로 선택한다. 이 단계는 `RunBuildState`를 바꾸지 않는다. 새 `RestCommitCoordinator`는 REST 시작 시 커밋된 백팩 상태, `RunBuildState`, `RunRouteState`, `FateController` 객체를 고정한다.

커밋 요청은 다음을 모두 확인한다.

1. REST 세션에 미확정 미리보기·버퍼·가방·조합·보상/상자 차단 사유가 없다.
2. 세션 해석 결과가 유효하고 최종 스냅샷과 modifier가 존재한다.
3. 보류 Fate가 현재 후보이며 아직 선택되지 않았고 현재 `RunBuildState`에 결합되어 있다.
4. 경로는 활성 전장이 아니고, 최종 결속이 아니며, 이미 적어도 한 학교를 클리어했고 유효한 미방문 임시 학교를 가진다.
5. 조정자의 소유자 묶음과 실제 Fate 결합이 REST 시작 때의 것과 같다.

사전검증이 통과하면 조정자는 세션 스냅샷과 modifier를 확정하고, 보류 Fate를 반영하고, 임시 경로를 활성화한다. 각각은 직전 사전조건으로 성공이 보장되는 최소 호출이다. 같은 구성의 REST 트랜잭션은 성공 뒤 다시 커밋하거나 새 세션을 시작할 수 없다. 다음 Workbench는 새 `configure()`로 새 원자 트랜잭션을 연다.

## 실패와 재진입

- 사전검증 실패, 중복 커밋, 잘못된 Fate/경로, 활성 조합/미리보기는 `false`를 반환하고 확정 상태를 바꾸지 않는다.
- 활성 REST 동안 `configure()`는 거부되어 다른 상태 객체로 소유자 묶음을 바꾸지 못한다.
- Fate 후보 재시작/재선택은 기존 MVP-3의 한 REST 한 선택 계약을 유지한다.
- 이 패키지는 실행 중 외부 시그널 재진입을 추가하지 않는다. 새 코드는 커밋 뒤에만 완료 상태를 노출한다.

## 검증

- GUT RED/GREEN: 보류 Fate 비변경, 성공 한 번 확정, 실패 무변경, 중복/재진입, 소유자 교체, 잘못된 route/Fate/session.
- 기존 Fate/Route/Backpack/RunBuild 단위 회귀와 전체 GUT.
- Godot import와 main-scene headless smoke. UI가 범위 밖이므로 이 패키지는 도메인 런타임 검증까지만 주장한다.
- 사람 사용성, 플레이 경험, 디바이스/내보내기는 별도 `NOT_RUN` 유지.
